# PRD: Помодоро Трекер

> Generated: 2026-06-17 | Status: Draft | Version: 0.5

---

## 1. Executive Summary

Помодоро Трекер — нативное Android-приложение на Kotlin для управления концентрацией по методу Pomodoro с привязкой к проектам. Пользователь выбирает проект (работа, чтение, учёба и т.д.), для каждого настраивает свой пресет (длительность фокуса/паузы, количество помидорок, цвета, звуки), и запускает классический круговой таймер с заполняющимся сектором. Ключевая ценность — персонализация ритма работы под конкретную задачу и борьба с «забыванием» вернуться к работе через alert при простое. Целевое устройство — Samsung Galaxy A51, с поддержкой portrait и landscape.

## 2. Problem Statement

Большинство Pomodoro-приложений предлагают единые глобальные настройки таймера, не учитывая, что разные виды деятельности требуют разного ритма: для интенсивной работы подходит 25/5, для чтения книги — 45/15. Пользователю приходится вручную перенастраивать таймер при переключении между задачами, что создаёт трение и снижает следование методу.

Вторая болевая точка — «выпадение» из ритма: помидорка закончилась, пауза прошла, но пользователь отвлёкся и не запустил новый цикл. Существующие решения молча останавливаются, и сессия фактически срывается. Нужен механизм, который активно напоминает вернуться к работе (мигание дисплеем каждые X минут при простое).

Третья — отсутствие визуальной привязки таймера к проекту: пользователь теряет контекст, над чем именно он сейчас работает и сколько помидорок осталось в сессии.

## 3. Target Audience

| Segment | Description | Pain Point | How product helps |
|---------|-------------|------------|-------------------|
| Студенты / самообучающиеся | Учатся по разным предметам, чередуют чтение, конспектирование, решение задач | Разным задачам нужен разный ритм; легко отвлечься и не вернуться | Пресеты по проектам + alert при простое возвращают в фокус |
| Фрилансеры / удалёнщики | Ведут несколько проектов параллельно, нужно учитывать время по каждому | Перенастройка таймера под задачу, потеря контекста проекта | Карусель проектов, отдельные пресеты, цвета и daily goal на проект |
| Любители продуктивности | Используют Pomodoro как привычку, ценят кастомизацию и визуал | Шаблонные приложения без гибкости настроек | Полная кастомизация цветов, звуков, длинных перерывов, автостарта |

## 4. Goals & Success Metrics

### MVP Goals
- Запустить рабочий классический Pomodoro-таймер (круг с заполнением сектором, tap = пауза/продолжить).
- Реализовать систему проектов с индивидуальными пресетами и переключением свайпом.
- Гарантировать, что в один момент времени активен только один таймер.
- Реализовать alert при простое (мигание дисплеем каждые X минут).
- Поддержать portrait и landscape на Samsung A51.

### Success Metrics
| Metric | Target | How to measure |
|--------|--------|----------------|
| Завершаемость сессии | ≥ 70% запущенных помидорок доведены до конца | Локальная аналитика: completed / started |
| Возврат после простоя | ≥ 50% alert-ов приводят к запуску новой помидорки в течение 2 мин | Локальное событие: alert → start |
| Достижение daily goal | ≥ 40% активных дней цель выполнена | completed pomodoros vs daily goal |
| Удержание (retention D7) | ≥ 30% | Дни с ≥1 запущенной помидоркой за 7 дней после установки |
| Стабильность | Crash-free sessions ≥ 99% | Crash-репортинг (напр. Firebase Crashlytics) |

## 6. User Stories

### US-001: Запуск помидорки по проекту
**As a** пользователь, **I want to** выбрать проект и запустить таймер, **so that** я фокусируюсь над конкретной задачей с подходящим ритмом.

**Acceptance Criteria:**
- [ ] `GIVEN` открыт главный экран с выбранным проектом `WHEN` пользователь нажимает play `THEN` запускается таймер с пресетом проекта и круг начинает заполняться сектором
- [ ] `GIVEN` запущена помидорка `WHEN` отображается экран `THEN` цвет интерфейса соответствует цвету режима «Помодоро» проекта
- [ ] `GIVEN` уже идёт активный таймер `WHEN` пользователь пытается запустить другой `THEN` система не допускает второй параллельный таймер (предыдущий должен быть остановлен/завершён)

**Notes:** Единственность таймера — глобальный инвариант приложения.

**Раскладка главного экрана (портрет, сверху вниз)** — за основу взят UX классического Pomodoro-трекера, с нашими отличиями:
```
┌─────────────────────────────┐
│                      [≡]     │  ← бургер-меню справа в углу (настройки/проекты)
│                              │
│         ◓  ЦИФЕРБЛАТ         │  ← круг с заполнением сектором, внутри play-pause; tap = пауза, hold ~5с = reset
│                              │
│        ● ● ● ○ ○ ○ ○ ○        │  ← буллеты сессии (закрашено = сделано, напр. 3 из 8)
│         Название проекта      │  ← имя активного проекта
│                              │
│      Pomodoro: 25 MIN         │  ← лейбл типа фазы; на stop = длительность, в работе = обратный отсчёт; tap = смена типа фазы (F-021)
│                              │
│                              │
│           reset               │  ← мелкий лейбл reset внизу, виден только на паузе (F-020)
└─────────────────────────────┘
```
Свайп влево/вправо по экрану (только на stop/pause) — карусель проектов. В активном режиме экран минималистичен: циферблат, play-pause, название проекта и буллеты остаются; reset-лейбл и доступ к карусели/меню скрыты/заблокированы. Landscape — те же элементы в горизонтальной компоновке (циферблат слева, текстовые элементы справа). [TBD — точная landscape-компоновка при дизайне]

### US-002: Пауза и продолжение по тапу
**As a** пользователь, **I want to** ставить таймер на паузу нажатием на циферблат, **so that** я могу прерваться, не теряя прогресс помидорки.

**Acceptance Criteria:**
- [ ] `GIVEN` идёт активная помидорка `WHEN` пользователь тапает по циферблату `THEN` таймер останавливается, заполнение сектора замирает, иконка меняется на play
- [ ] `GIVEN` таймер на паузе `WHEN` пользователь тапает по циферблату снова `THEN` таймер продолжается с того же момента
- [ ] `GIVEN` таймер на паузе `WHEN` приложение свёрнуто и открыто заново `THEN` состояние паузы и оставшееся время сохранены

**Notes:** Тап по циферблату и кнопка play-pause внутри круга выполняют одно действие.

### US-003: Переключение проектов свайпом
**As a** пользователь, **I want to** свайпать карусель проектов на главном экране, **so that** я быстро переключаюсь между задачами.

**Acceptance Criteria:**
- [ ] `GIVEN` таймер остановлен или на паузе `WHEN` пользователь свайпает влево/вправо `THEN` активный проект меняется, обновляются название, буллеты помидорок, цвета и пресет
- [ ] `GIVEN` идёт активная (не на паузе) помидорка `WHEN` пользователь свайпает `THEN` свайп игнорируется — карусель недоступна, экран в режиме минимализма

**Notes:** Переключение проектов разрешено только в состоянии stop/pause. Во время активной помидорки UI минималистичен (см. US-007).

### US-004: Alert при простое (смена цветов)
**As a** пользователь, **I want to** видеть смену цветов экрана при простое (когда экран горит), **so that** я не забываю запустить следующую помидорку, но меня не дёргают, когда я отошёл.

**Acceptance Criteria:**
- [ ] `GIVEN` помидорка/пауза завершена, новая не запущена, always-on включён и экран активен `WHEN` проходит X минут простоя `THEN` экран меняет цвета между active/pause как визуальный alert
- [ ] `GIVEN` состояние простоя продолжается с горящим экраном `WHEN` проходит каждые следующие X минут `THEN` смена цветов повторяется
- [ ] `GIVEN` экран выключен (пользователь отошёл) `WHEN` идёт простой `THEN` приложение ничего не делает — никаких пробуждений экрана, звуков или вибрации
- [ ] `GIVEN` пользователь запускает новую помидорку `WHEN` таймер активен `THEN` alert-цикл прекращается

**Notes:** X задаётся в настройках. Намеренно не используем wake lock / пробуждение экрана — alert работает исключительно как визуальная индикация на уже горящем дисплее. Это снимает все проблемы с Doze/battery optimization.

### US-005: Настройка проекта и пресетов
**As a** пользователь, **I want to** создавать и редактировать проекты с их пресетами, **so that** каждый вид деятельности имеет свой ритм и вид.

**Acceptance Criteria:**
- [ ] `GIVEN` экран настроек `WHEN` пользователь создаёт проект `THEN` он задаёт название, длительность фокуса/паузы, кол-во помидорок, цвета фокуса/паузы, daily goal
- [ ] `GIVEN` пользователь выбирает быстрый пресет (25/5, 30/10, 45/15) `WHEN` применяет `THEN` поля длительностей заполняются, остаются редактируемыми
- [ ] `GIVEN` существующий проект `WHEN` пользователь редактирует или удаляет его `THEN` изменения сохраняются локально и отражаются в карусели

**Notes:** **На проект:** название, длительность фокуса/паузы, кол-во помидорок, цвета active/pause, daily goal, long break (галочка вкл/выкл + длительность + после скольких помидорок). **Глобально:** звуки старта/окончания, вибрация, always-on display, alert при простое (X мин), autostart, время конца дня (когда сутки считаются завершёнными), язык интерфейса (English / Русский).

### US-006: Завершение сессии и long break
**As a** пользователь, **I want to** получать длинный перерыв после серии помидорок, **so that** я полноценно отдыхаю между блоками работы.

**Acceptance Criteria:**
- [ ] `GIVEN` для проекта включён long break после N помидорок `WHEN` завершается N-я помидорка этого проекта `THEN` запускается длинный перерыв вместо обычной паузы (счётчик ведётся отдельно по проекту)
- [ ] `GIVEN` long break для проекта выключен галочкой `WHEN` завершается помидорка `THEN` всегда идёт обычная пауза
- [ ] `GIVEN` включён autostart `WHEN` завершается помидорка/пауза `THEN` следующая фаза стартует автоматически со звуком/вибрацией согласно настройкам
- [ ] `GIVEN` достигнут daily goal проекта `WHEN` завершена целевая помидорка `THEN` показываются «фанфары» (анимация/звук поздравления)
- [ ] `GIVEN` наступило настроенное время конца дня `WHEN` начинается новый день `THEN` дневные счётчики помидорок и достижение целей сбрасываются по всем проектам

### US-007: Минимализм активной сессии и сброс помидорки
**As a** пользователь, **I want to** видеть во время фокуса только таймер, а при ошибке быстро сбросить помидорку, **so that** ничто не отвлекает, но я могу исправить случайный неверный запуск.

**Acceptance Criteria:**
- [ ] `GIVEN` идёт активная помидорка `WHEN` отображается главный экран `THEN` видны циферблат, кнопка play-pause, название проекта и буллеты прогресса (напр. 8 буллетов, 3 закрашены); настройки и карусель скрыты/недоступны
- [ ] `GIVEN` запущена помидорка (например, не того проекта/режима) `WHEN` пользователь удерживает play-pause ~5 сек `THEN` текущая помидорка сбрасывается, таймер возвращается в исходное состояние выбранного проекта
- [ ] `GIVEN` пользователь начал долгое нажатие `WHEN` идёт удержание `THEN` есть визуальная индикация прогресса сброса (чтобы случайный долгий тап не сбросил молча)

**Notes:** Короткий тап = пауза/продолжение (US-002), долгое удержание = сброс. Нужно явно различать жесты.

### US-008: Ручная смена типа фазы
**As a** пользователь, **I want to** вручную выбрать тип таймера (помодоро / короткая пауза / длинная пауза), **so that** я могу исправить ситуацию, когда после сбоя следующей идёт не та фаза.

**Acceptance Criteria:**
- [ ] `GIVEN` таймер остановлен или на паузе `WHEN` пользователь меняет тип фазы `THEN` таймер переключается на выбранный тип с соответствующей длительностью и цветом
- [ ] `GIVEN` система предложила «паузу», а пользователь готов работать `WHEN` он выбирает «помодоро» `THEN` запускается помидорка, а не пауза
- [ ] `GIVEN` пользователь сменил тип фазы вручную `WHEN` фаза завершается `THEN` счётчики помидорок/long break проекта обновляются корректно

**Notes:** Смена фазы — тапом по лейблу типа таймера под буллетами (см. раскладку главного экрана в US-001). Доступна в состоянии stop/pause.

- **Infrastructure:** Foreground Service для надёжной работы таймера в фоне. Alert при простое реализуется внутри сервиса/UI как смена цветов (без AlarmManager/WorkManager). Опционально Firebase Crashlytics для стабильности.

### Integrations
- Системные API: Notification (foreground service), Vibrator, AudioManager/SoundPool (звуки), PowerManager/WindowManager (always-on display, мигание экраном).

### Constraints
- **Целевое устройство:** Samsung Galaxy A51 (Android 11+, разрешение 1080×2400, 6.5"). UI тестировать на этом форм-факторе в обеих ориентациях.
- **Точность таймера в фоне:** Android агрессивно убивает фоновые процессы (особенно Samsung/One UI с battery optimization). Таймер обязан переживать сворачивание и блокировку → Foreground Service + persistent state.
- **Alert при простое:** реализуется как смена цветов active/pause на уже горящем экране (только при always-on). НЕ требует wake lock, exact alarm или пробуждения экрана → нет проблем с Doze/battery optimization. При выключенном экране alert не работает по дизайну.
- **Минимальная версия Android:** minSdk 29 (Android 10). targetSdk — актуальный на момент разработки.
- **Ориентация:** обязательны portrait и landscape без потери состояния таймера при повороте.
- **Локализация:** весь UI вынесен в string resources, поддержка English и Русский с переключением в настройках (in-app locale, напр. AppCompatDelegate / per-app language). Никаких хардкод-строк.

## 8. Architecture Overview

Рекомендуемая архитектура: MVVM + однонаправленный поток данных. Таймер живёт в Foreground Service как единый источник истины, UI подписывается на состояние.

```
[Главный экран (Compose/View)]  ←→  [TimerViewModel]
        ↕ (свайп, tap)                     ↕
[Экран настроек] ←→ [SettingsViewModel]    │
                                            ↓
                                  [TimerService (Foreground)]  ←─ единственный активный таймер
                                            ↓
                            [Repository] → [Room DB: Projects, Sessions]
                                         → [DataStore: глобальные настройки]
                                            ↓
                  [TimerService idle-timer] → Alert при простое (смена цветов active/pause, только при always-on + горящем экране)
                  [SoundPool] [Vibrator] [PowerManager/WindowManager] — глобальные эффекты старта/окончания/always-on
```

Ключевой инвариант: `TimerService` допускает только один активный таймер. ViewModel-и не держат собственное время — они читают состояние из сервиса.

## 9. Out of Scope

- **Аккаунты / облако** — MVP офлайн; синхронизация отложена (F-106).
- **Статистика и графики** — в Post-MVP (F-100); MVP показывает только текущую сессию и daily goal.
- **Виджеты и управление из шторки** — Post-MVP (F-101, F-102).
- **Кросс-платформенность (iOS/Web)** — только Android.
- **Кастомные/загружаемые звуки** — MVP использует встроенный набор (F-105 отложено).
- **Интеграции с таск-менеджерами** — не входит.
